# WP-105 — `/v1/stream` WebSocket Transport

For the `Connection` auth/clock-sync seam and how this fits the rest of
the pipeline, see `techdocs/ARCH.md`. For live-run verification steps,
see `PREFLIGHT.md` §9.

## What it is

WP-105 (Phase 14 of the Architecture Fixing sprint) wires the previously
built `Connection` (Phase 13), `api/ws/messages.py`, and
`InteractionWorker` (Phase 12) pieces together behind the `/v1/stream`
WebSocket route, turning SPEC §7.2's message sequence into calls against
those already-built components.

Start the server:

```bash
python -m uvicorn api.app:app --host 0.0.0.0 --port 8765
```

Endpoint:

```text
ws://127.0.0.1:8765/v1/stream
```

Smoke test:

```bash
python -m scripts.run_manual_stream --silence --no-play
```

For a real microphone interaction:

```bash
python -m scripts.run_manual_stream --seconds 3
```

## What's implemented

Per `api/ws/stream.py`'s module docstring, this scaffold does:

- accept a connection and authenticate it (see caveat below);
- run the SPEC §7.4 clock-sync handshake;
- track one in-flight session per connection, against both `Connection`
  (local) and `SessionRegistry` (host-wide);
- buffer uplink `audio_frame` bytes;
- submit a completed utterance to the `InteractionWorker` queue;
- stream the response and TTS audio back to the client;
- reclaim a session abandoned mid-utterance once it exceeds SPEC §7.4's
  30s inactivity timeout (`_StreamSession.run_reaper`), persisting a
  `session_timeout` degraded trace and notifying the client — a session
  already handed to the worker is left alone so queue wait or TTS
  playback is never mistaken for client inactivity.

## What's deliberately deferred / open

- **Real device authentication.** `default_dev_authenticate` accepts
  every connection; SPEC §7.4's device-token check is unimplemented.
  BL-03 defers this past the prototype defense — a plain WebSocket is
  considered sufficient on a controlled bench network. This is a known
  gap, not scaffold debt to close in a hurry.
- **Real playback-rate pacing** on the downlink — see
  `api/ws/downlink.py`.
- **Writing `condition_report`'s `degradation_reason`** onto a
  decision-trace row (SPEC §7.3) — logged only for now.
